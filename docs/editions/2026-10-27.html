What an agent pipeline counts on: hook counts, rerun stability, and actions that can disappear

Back to Radar

October 27, 2026

Today's theme is the counts and dependencies a team trusts around coding agents: subagent hooks that fired too often, an agent GitHub Action that is no longer published, test reruns that report how stable a result is, and malware that collects agent logins, which decides whether your audit numbers, your CI pipelines, and your developers' accounts can be relied on.

Main signal

Numbers and pipeline steps around an agent can change under you without any change on your side. Claude Code 2.1.311 fixes subagent stop hooks that ran about twice a minute per subagent instead of once, so any count built on them was likely inflated, OpenCode 2.2.0 stops publishing its GitHub Action and tells users to remove it from workflows, and promptfoo 0.125.0 adds stability reporting across repeated tests. A hook count, a pass rate, or a pipeline step is only as good as the tool version that produces it.

"Agent audit counts, test pass rates, and pipeline steps are evidence only while someone owns how they are produced, so re-baseline each one whenever the agent tool beneath it changes."

1. Subagent stop hooks fired twice a minute, so counts built on them were wrong Experiment now

Layer: evidence, orchestration

Claude Code 2.1.311 (Oct 26) fixes SubagentStop hooks running about twice a minute per subagent instead of once when it finishes, and fixes Write and Edit stalling up to 5 seconds and reporting 0 lines changed on edits of thousands of lines. It also makes standard-context sessions compact the conversation and continue instead of stopping with a "Usage credits required for 1M context" error.

Why it matters: If a dashboard, audit log, or cost rule counts subagent completions or changed lines, re-baseline it after upgrading and add a check that each subagent produces exactly one stop event.

2. Evaluation tooling starts reporting how stable a result is across reruns Experiment now

Layer: verification, policy

promptfoo 0.125.0 (Oct 23) adds stability reporting across repeated tests, a safe mode that disables inline JavaScript execution, and trace span filtering by attributes. It also makes the Claude Agent and Codex SDK providers opt-in, a breaking change. The release notes list these without detail and I did not read the documentation, so check how stability is calculated before relying on it.

Why it matters: One pass of a nondeterministic agent test is a sample of one, so report the pass fraction over repeated runs and run shared evaluation configs in safe mode.

3. An agent vendor stops publishing its GitHub Action Watch closely

Layer: orchestration, execution

OpenCode 2.2.0 (Oct 27) lists a breaking change, "The OpenCode GitHub Action is no longer published," and says only to remove it from workflows, with no replacement named. A separate action release on Oct 24 had pinned actions/cache to a commit SHA.

Why it matters: Inventory every third-party agent action in your workflows, pin each by commit SHA, and plan the replacement before a run that depends on one fails.

4. Infostealer malware now collects the login files of AI coding tools Watch closely

Layer: policy, execution

Infosecurity Magazine reports that the Aoki infostealer, first described by Symantec on Oct 15, collects credential and session files for Claude, ChatGPT, Codex, Cursor, Copilot, Gemini, and AWS, such as .claude.json and the Codex config.toml, and Gridinsoft cites a Check Point analysis dated Oct 23. It runs on an already infected machine, no provider breach is reported, the Check Point attribution rests on that one source, and I read search summaries rather than the original reports.

Why it matters: A stolen agent session lets an attacker spend the developer's quota and reach connected repositories and CI, so add revoking agent sessions and tokens to your response plan for a compromised laptop.

Field lines

  • "One pass of an agent test is a sample of one, so report how often the same test passes across repeated runs." (promptfoo 0.125.0 release notes)
  • "A GitHub Action your agent pipeline calls can be withdrawn by its maintainer, so inventory and pin every agent action you depend on." (OpenCode 2.2.0 release notes)
  • "Login files that AI coding tools keep on a laptop are what infostealer malware now collects, so treat a compromised developer machine as a compromised agent account." (Infosecurity Magazine on the Aoki infostealer)

Copilot CLI 1.0.104 starts managed-model "fusion" sessions on Auto and applies fusionTier settings, and Gemini CLI nightlies now treat a project spending cap as a terminal quota error, so cost limits and model choice are handled by the runtime. Consulting angle

Ask this week: Which dashboards, audit counts, or pipeline steps in your agent setup depend on a tool version you upgraded this month, and who re-checked that they still measure what they claim?
