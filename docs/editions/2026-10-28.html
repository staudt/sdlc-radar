What bounds an agent: the harness attackers copy, hook limits, and marketplace URLs

Back to Radar

October 28, 2026

Today's theme is the limits around coding agents: CrowdStrike reports intruders running the same supervisor, executor, and skills setups engineering teams use, while Claude Code and Codex releases cap hooks and tighten plugin marketplace URLs, which decides how much damage a misused or misconfigured agent can do to your code, credentials, and pipelines.

Main signal

The controls around an agent harness now matter as much to security as to cost, because the people attacking you build harnesses the same way you do. CrowdStrike's report describes four intruder groups driving Claude Code through supervisor and executor loops and a library of 819 downloaded skills, and concludes the main limit on scale is token budgets, not engineering. Meanwhile Claude Code 2.1.312 caps concurrent hooks and Codex 0.165.0 closes a marketplace URL check that could send Git to a different host than the one approved, so budgets, hook limits, and URL checks are the places a harness is actually bounded.

"Intruders and engineering teams now run the same agent loops, so budgets, approvals, and URL allow-lists are security controls as well as cost controls."

1. Intruders run agent harnesses with state machines and skill libraries Watch closely

Layer: orchestration, policy

CrowdStrike's report (Oct 21), covered by CIO Dive and Security Brief (Oct 28), documents four actors who used agents to pick tasks and run commands in intrusions from May to August 2026. One paired a Claude Code supervisor following a predefined state machine with an executor, and the simplest used 819 mostly public skills and still had to step in when model guardrails interrupted it. Victims are unnamed and the figures are CrowdStrike's own, and I read search summaries and secondary coverage, not the full report.

Why it matters: Your harness patterns, skill libraries, and budgets are also the attacker's, so audit which skills your agents load and cap spend and tool scope per run.

2. A coding agent caps how many hooks run at once Experiment now

Layer: policy, orchestration

Claude Code 2.1.312 (Oct 27) limits prompt and agent hooks to 24 at a time per session, plus 12 that have waited past their timeout. It also fixes Claude overwriting a very large CLAUDE.md or rules file after reading only its start, and switches Bedrock, Vertex, and Foundry deployments with custom model names to the shorter system prompt unless CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 is set.

Why it matters: If quality or policy gates run as hooks, test what happens to them when a session fans out past the cap, because the notes do not say, and re-baseline agent behavior on gateways that use custom model names.

3. A marketplace URL check let Git connect to an unapproved host Experiment now

Layer: policy, execution

Codex 0.165.0 (Oct 27) rejects backslashes in the userinfo part of marketplace URLs, closing a gap where Git could connect to a different host than the one checked against allowed patterns. It also makes memory v2 the default for new profiles, allows changing reasoning effort mid-conversation, and adds a Vertex AI provider and the GPT-6.1 Terra name to model catalogs; I found no OpenAI announcement of that model, so treat it as unconfirmed.

Why it matters: Treat every plugin or skill source URL as a trust boundary, upgrade agents that install from marketplaces, and note that new default memory changes what a rerun starts from.

Bet tracker

Bet: Token and spend budgets will become a primary security control for agent fleets, not just a cost control. Why: CrowdStrike concludes that token budgets, not engineering complexity, limit how far an AI-run intrusion scales (CIO Dive). Source: CrowdStrike.
