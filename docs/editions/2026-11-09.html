When nobody is there to approve: deny instead of prompt, enforced budgets, and autopilot that stops asking

Back to Radar

November 9, 2026

Today's theme is unattended coding agents: Claude Code 2.1.319, an OpenAI Agents SDK preview, and a Copilot CLI pre-release each change what happens when an agent hits an action that would normally wait for a person, which decides whether a CI job on your source code, credentials, and cloud spend hangs, fails, or quietly proceeds.

Main signal

The approval prompt is being replaced by a decision made in advance, and the default for an unanswered question is now a setting you must choose. Claude Code v2.1.319 (Nov 6) adds permissions.denyInsteadOfPrompting and makes claude -p exit 1 when auto mode refuses actions. OpenAI Agents SDK v0.24.0-alpha.7 (Nov 8) adds a RunBudget and a strict write policy by default. A pipeline that keeps its old settings can now stall on a prompt nobody answers, or proceed on a policy nobody wrote down.

"For an unattended coding agent, the safe default for a question nobody answers is no, and the pipeline should fail visibly when that happens."

1. Claude Code 2.1.319 can deny a tool call instead of waiting for a prompt, and fails closed behind a gateway Experiment now

Layer: policy, verification

Claude Code v2.1.319 (Nov 6) adds permissions.denyInsteadOfPrompting, which denies a tool call that would wait on a permission prompt. Auto mode behind an LLM gateway with telemetry or feature flags off now asks or denies calls it cannot verify instead of falling back to the built-in classifier, unless CLAUDE_CODE_AUTO_MODE_SERVER=0 is set. Bash deny and ask rules now catch commands written with quoted words, and claude -p exits 1 when auto mode refuses actions.

Why it matters: A headless job that used to fall back silently can now fail or deny, so rerun your pipeline on this version with a gateway configured and confirm the exit code and the quoted-word deny rule behave as your policy says.

2. OpenAI Agents SDK alpha.7 adds an enforced run budget and strict write policy by default Watch closely

Layer: policy, orchestration

OpenAI Agents SDK v0.24.0-alpha.7 (Nov 8, pre-release) adds RunBudget to limit root requests, reported tokens, or estimated cost, plus CustomStorage for durable root sessions. New Environments default to a strict write policy, MCP approval modes are renamed "native" and "preapproved", and the default reasoning effort for some models moves from low to medium, which can change cost and latency.

Why it matters: This is a preview with breaking changes, so prototype the budget and the strict write default on a branch, and expect run cost to move if you rely on the old reasoning-effort default.

3. Copilot CLI 1.0.108 pre-releases let autopilot with assisted permissions run without stopping Watch closely

Layer: policy, execution

Copilot CLI v1.0.108-0 (Nov 7, pre-release) notes that Autopilot with Assisted Permissions no longer stops for permission prompts, and v1.0.108-1 (Nov 7) restarts a running local MCP server after /cd when the sandbox is on, so the new directory's denied paths apply. I read the release notes, not the code, so what Assisted Permissions decides in place of a person is unverified.

Why it matters: When autopilot stops asking, your allow and deny rules are the only approval left, so write test cases for them before this reaches the stable build.

Field lines

  • "A coding agent in CI should deny a risky action it cannot get approved, and the job should exit non-zero so someone sees it." (Claude Code v2.1.319 release notes)
  • "An agent run's cloud spend needs a limit the harness enforces, because a budget the agent is only asked to respect is not a control." (OpenAI Agents SDK v0.24.0-alpha.7 release notes)
  • "Once a coding agent's autopilot stops asking for permission, its allow and deny rules are the entire approval process, so test them like production code." (Copilot CLI v1.0.108 release notes)

Bet tracker

Strengthening: Agent control planes will move outside the agent's own process and network reach. Claude Code 2.1.319 refuses to fall back to its built-in classifier when a gateway cannot verify a call, and the Agents SDK now defaults new Environments to a strict write policy, so the safe behavior is set by the surrounding infrastructure, not the session (Claude Code v2.1.319, Agents SDK v0.24.0-alpha.7).

Consulting angle

Ask this week: When your coding agent in CI reaches an action that needs a person, does the job deny, hang, or proceed, and which test in your pipeline proves it?
