Proof that agent controls fire, and secrets that stop leaking at the plumbing

Back to Radar

October 22, 2026

Today's theme is proof that agent controls are working: a Claude Code event that logs every tool call a safety control stopped, an agent workflow release that refuses to publish artifacts when secret redaction fails, and an editor fix that kept agent credentials out of the machine's process list, which decides whether you can show that your guardrails fire and whether your keys stay private.

Main signal

A control you cannot observe is a control you cannot trust. Claude Code 2.1.307 now emits one telemetry event for every tool call that a permission rule, auto mode, a hook, or the sandbox stopped, prompted, or sent back, and GitHub Agentic Workflows v0.93.0 makes agent artifact uploads fail when redaction does not succeed. Zed 1.25.2 stops secrets passed to external agents and MCP servers from showing up in the local process list. If you cannot count what your controls blocked, or a secret can be read by any program on the machine, a silent failure looks the same as a safe week.

1. Every blocked tool call becomes one telemetry event Experiment now

Layer: evidence, policy

Claude Code 2.1.307 (Oct 21) adds the claude_code.safety_event OpenTelemetry event for each tool call that a permission rule, auto mode, a safety check, a hook, or the sandbox stopped, prompted, or sent back. It also fixes /permissions so a recently denied shell command is shown by name, and so auto mode honors an approval given from there on a retried command.

Why it matters: Add a dashboard of safety events per week for one agent job and alert when the count drops to zero, since a control that never fires may be switched off, not idle.

2. Agent workflows now refuse to publish when redaction fails Watch closely

Layer: policy, evidence

GitHub Agentic Workflows v0.93.0 (Oct 21, pre-release) requires redaction to succeed before agent artifacts are uploaded, rejects unsafe action pins, blocks OTLP token injection through env files, and makes admission jobs opt-in, a breaking change. Its health tool and routing analytics land in the same release.

Why it matters: Redaction that blocks the upload gives you a fail-closed leak control, but this is a pre-release, so trial it on a non-critical repository and check which admission jobs you relied on before upgrading.

3. Agent and MCP secrets no longer show up in the process list Experiment now

Layer: execution, policy

Zed 1.25.2 (Oct 21; first fixed in the 1.25.0 pre-release on Oct 14) stops environment variables and secrets passed to external agents and MCP servers in remote projects from being visible in the local machine's process list. The same release adds context compaction and session notices for external agents over ACP.

Why it matters: Check how your harness hands credentials to agents and MCP servers, since any program on the same machine can read an environment variable shown in a process list, and prefer short-lived scoped tokens over long-lived keys in env blocks.

Field lines

Bet tracker

Bet: Agent control planes will move outside the agent's own process and network reach. Strengthening. GitHub Agentic Workflows v0.93.0 makes the workflow runtime, not the agent, refuse an artifact upload when redaction fails, and Claude Code 2.1.307 reports blocked calls from the harness side.

Consulting angle

Ask this week: For one agent job, can you count how many tool calls your controls stopped last week, and would anyone notice if that number went to zero?
