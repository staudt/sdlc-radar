Agent limits move into the harness: write boundaries, split policies, and sandbox file permissions

Back to Radar

October 30, 2026

Today's theme is who enforces an agent's file and tool access: a Claude Code setting that blocks writes outside the working directories in every permission mode, opencode managed policy that now separates MCP servers, skills, and plugins, and Inspect AI sandboxes that read files as the agent's own user, which decides whether your source tree, your tool allow-lists, and your evaluation scores reflect the limits you meant to set.

Main signal

Agent limits are moving out of instructions and into settings the harness enforces, one surface at a time. Claude Code 2.1.314 adds a setting that makes Write, Edit, and NotebookEdit refuse paths outside the working directories in every permission mode, opencode 2.2.3 splits its managed policy into separate MCP, skill, and plugin permissions, and Inspect AI 0.3.286 makes sandbox file reads and writes obey the agent's user permissions. An agent that can write outside its project can overwrite files and configuration you never meant it to touch, and a policy written for the old keys may no longer cover the tools you thought it did.

"A write boundary only counts if it holds in the permission mode your developers actually use, so test it in the most permissive one."

1. Claude Code adds a write boundary that holds in every permission mode Experiment now

Layer: policy, execution

Claude Code 2.1.314 (Oct 30) adds permissions.blockWritesOutsideWorkingDirectories, so Write, Edit, and NotebookEdit refuse paths outside the working directories in every permission mode. It also makes claude -p print startup errors and exit with code 1 instead of exiting 0 silently, and caps PreCompact hook output at 10,000 characters so it cannot break compaction.

Why it matters: Turn the setting on in managed configuration and add a negative test that tries a write outside the project in the most permissive mode, and check that CI jobs now fail on the new non-zero exit instead of passing on an agent that never started.

2. opencode splits managed policy into separate MCP, skill, and plugin permissions Experiment now

Layer: policy

opencode v2.2.3 (Oct 30) lists a breaking change to managed policy: integration.use now covers only integrations, and new mcp.use, skill.use, and plugin.use actions control the others. The same release makes TUI plugins require OpenTUI 0.8 and moves speech, transcription, and video to an experimental SDK path. I read the release notes, not the policy documentation, so check what the old key covered before you migrate.

Why it matters: Per-surface permissions let you approve an MCP server without approving every skill and plugin, but any managed policy written against the old key needs rewriting and a test that a denied MCP server, skill, and plugin each stay denied.

3. Evaluation sandboxes start reading files as the agent's user Experiment now

Layer: verification, execution

Inspect AI 0.3.286 (Oct 28) makes sandbox file reads and writes enforce user permissions, and Docker read_file() now uses the container's default user, so callers who need privileged reads must pass user="root". It also lets tool approval see validated arguments and warns that human_cli cannot collect terminal recordings on older providers such as Kubernetes.

Why it matters: A grader that read files as root could see things the agent could not, so re-run a baseline evaluation after upgrading and expect some scores and sandbox providers to need changes.

Field lines

  • "A write boundary only counts if it holds in the permission mode your developers actually use, so test it in the most permissive one." (Claude Code 2.1.314 release notes)
  • "When an agent platform splits its managed policy into separate permissions for MCP servers, skills, and plugins, rewrite your policy and test each one." (opencode v2.2.3 release notes)
  • "An evaluation that reads files as root sees more than the agent could, so re-run your agent test baselines whenever the sandbox starts enforcing the agent's own permissions." (Inspect AI 0.3.286 release notes)
