Main signal

GovernanceProduction now

The files an agent writes to remember your approvals now leak credentials, and secret scanners were not built to find them.

Security firm Apiiro scanned every public copy of Claude Code's .claude/settings.local.json on GitHub between Nov 1 and Nov 3, and published on Nov 6. When a developer picks "Yes, and don't ask again", Claude Code saves the approved command as an allow rule, word for word. A password typed into that command is saved with it. Of 104,185 public copies, 1,122 held at least one real secret: 1,379 distinct credentials, including SSH logins, GitHub and npm tokens and AWS keys (The Hacker News, TechSpot).

The part that matters for delivery teams: TruffleHog flagged 57% of those files, gitleaks 50%, and neither flagged 215, because the passwords sat inline in commands such as PGPASSWORD= rather than in known key formats (Cybernews). Apiiro says Claude Code was the only one of 16 agents it reviewed that stores approved commands in project files by default. Anthropic's Claude Code lead said the team is looking at secret scrubbing; no fix appears in the release notes through 2.1.322 (Nov 10). Figures are Apiiro's, and it did not test whether the keys still work.

Why it matters: Agent folders are now part of the repository's attack surface, and a passing secret scan does not cover them. Gitignore them in org templates, scan them with rules for inline passwords, and rotate anything ever committed.

"The approvals your coding agent remembers can include the passwords you typed, and the usual secret scanners miss about one leaked file in five."
Apiiro research, via The Hacker News and Cybernews, Nov 2026

More signals

QA and testingWatch closely

AI agents proved security properties of Signal's code down to compiled machine code, then proved the checker by planting known bugs.

Google DeepMind's AlphaProof Code (Nov 10) verified forward secrecy, post-compromise security and authentication for libsignal's PQXDH handshake and Triple Ratchet against compiled Arm code (SecurityWeek). People and agents draft specifications that experts review, agents write Lean proofs, Lean checks every proof, and about 1% of the work goes to a person. To test the method, the team reinserted two previously fixed libsignal bugs, and the system proved those builds violate the properties. It covers Google's build, not Signal's apps; results are vendor-reported.

Why it matters: The pattern transfers without formal methods: a checker the agent cannot argue with, human review spent on specifications and flagged items, and planted bugs that prove the checker can fail.

"When AI writes the proof, people should review the specification and the small share the checker flags, and plant known bugs to prove the checker can fail."
Google DeepMind, AlphaProof Code, Nov 10, 2026

GovernanceExperiment now

Copilot CLI now says so when an admin policy overrides a request to skip approvals.

Copilot CLI 1.0.110-2 (Nov 11, pre-release) warns when --yolo or --allow-all is ignored because bypass-permissions mode is disabled, including in non-interactive runs. A postToolUse hook that rewrites a shell command's output now changes what copilot -p prints, not only what the model sees.

Why it matters: A CI job that passes --yolo under a managed policy now leaves a trace in its log, so a mismatch between pipeline and policy becomes auditable. Search your logs for it after upgrading.

"When company policy overrides a pipeline's request to skip approvals, the run should say so in its log, or nobody knows which rule was in force."
GitHub Copilot CLI 1.0.110-2 release notes, Nov 11, 2026
