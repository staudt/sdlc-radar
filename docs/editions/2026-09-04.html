AI SDLC Radar

A focused briefing on AI software development, quality engineering, test automation, and agentic SDLC practices.

Main signal

AI assisted QA is starting to split into two distinct layers: specialized QE agents that reason about quality, and deterministic evidence systems that verify what those agents actually did. That distinction is becoming more important than simply adding more AI generated tests.

1. Agentic QE is becoming a real open source category

Experiment now

The open source Agentic Quality Engineering Fleet has grown into a substantial implementation rather than a demo. The repository describes 60 specialized QE agents, support across 11 coding agent platforms, risk weighted coverage analysis, flaky test detection, security scanning, test generation, MCP integration, and persistent learning across sessions.

Why it matters: this is one of the clearest examples of QA being modeled as a collection of specialized engineering capabilities rather than a single test generation agent. The architecture separates concerns such as test generation, coverage, security, requirements validation, quality gates, and defect intelligence.

Maturity: early but serious. The breadth is impressive, although claims around learned optimization and multi agent coordination still need independent validation before enterprise adoption.

2. Playwright CLI adoption exposes a new supply chain quality concern

Watch closely

Playwright CLI continues to become the preferred browser interface for coding agents, but version 0.1.19 triggered a useful warning for enterprise teams. A Playwright issue reported that the package lost npm trusted publisher and Sigstore or SLSA provenance metadata after the publishing pipeline moved to Microsoft ESRP.

Why it matters: AI agents increasingly install and execute development tooling automatically. A package can remain functionally correct while its supply chain trust posture regresses. Traditional test pipelines rarely treat provenance continuity as a quality signal, but agentic environments may need to.

3. Test quality needs its own gate, not just pass rate

Experiment now

A large scale study of more than 200,000 test artifacts found that agent generated tests can look strong by conventional metrics while introducing different risks. AI generated tests showed broader edge case coverage than human tests, but also a higher likelihood of flakiness, especially from file I/O and nondeterministic behavior.

Why it matters: an agent that generates ten passing tests is not necessarily improving the suite. AI generated test acceptance should evaluate assertion strength, edge case relevance, isolation, determinism, duplication, and mutation resistance rather than only execution success and coverage.

Beyond Test Presence: Assessing the Quality and Robustness of Agent Generated Tests

Emerging pattern

  • QA agents are becoming specialized rather than monolithic.
  • Agent generated evidence needs independent verification.
  • Passing tests are becoming an insufficient quality signal for AI generated code and tests.
  • Supply chain trust is becoming part of agentic SDLC quality architecture.
  • MCP and CLI choices increasingly affect security, context efficiency, and governance.

Consulting angle

  • How is the quality of AI generated tests evaluated beyond pass rate and coverage?
  • Can agent actions be independently reconstructed from logs, traces, and repository diffs?
  • Are tool and package provenance changes detected automatically?
  • Are QA capabilities split into narrow, testable agent responsibilities rather than one broad autonomous agent?
  • Can quality gates reject AI generated work even when the primary test suite passes?

The broader opportunity for QA architecture is increasingly clear: AI coding agents need a verification system around them, not merely more automated tests inside them.
