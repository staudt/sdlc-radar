AI SDLC Radar

A focused briefing on AI software development, modern SDLC practices, QA, test automation, and open source research.

Main signal

Closed loop verification is outperforming one shot generation, while LLM as a judge is proving too unreliable to serve as the sole quality gate for complex agent workflows.

Generate → execute → measure → refine

This is becoming a stronger pattern than simply asking a model to generate tests and trusting the result.

1. AgentDV shows what useful AI generated testing actually looks like

Experiment conceptually now

AgentDV applies an agentic loop to hardware verification. The domain is RTL rather than web or API testing, but the architecture is highly transferable to software QA.

The framework combines LLM guided analysis, test construction, actual simulation, runnability filtering, grounded checks against the design, coverage measurement, and iterative regeneration based on measured gaps.

The researchers report that direct single shot prompting failed to produce a valid coverage producing environment on their benchmarks. The closed loop AgentDV approach performed substantially better, reaching an average 80.9% pass rate with Claude Sonnet 4.6 and producing measurable line and branch coverage.

Why it matters for QA: the agent does not decide that its own tests are good. The environment gives it executable evidence and coverage gaps, then the agent reacts to that evidence.

Explore application → generate tests → execute → inspect failures and coverage → identify gaps → regenerate targeted tests

2. AgentJudgeBench is a warning against using an LLM judge as your quality gate

Add to assessment guidance now

AgentJudgeBench, accepted at EMNLP 2026, evaluates LLM judges on 3,808 structured agent tool calling workflows across multiple difficulty levels.

The important result is that judge reliability degrades as workflow complexity increases. On hard tasks without ground truth, all six evaluated judges converged into a relatively narrow 77% to 82% alignment range regardless of model scale.

The study also found that giving judges ground truth did not consistently solve the problem. Structured rubrics helped in some configurations, but improvements did not generalize uniformly.

Why it matters: many emerging AI SDLC designs use a second model to review the first model's work. This can be useful, but it should not be mistaken for an objective quality gate.

  • Best: deterministic executable evidence, tests, static analysis, contracts, schemas, coverage, formal checks
  • Useful supplement: structured LLM evaluation with explicit rubrics
  • Weak: open ended model asks another model whether the output looks correct

Emerging pattern

  • AgentDV improves by trusting tool grounded execution and coverage signals.
  • AgentJudgeBench shows the limitations of trusting another LLM's interpretation as the final arbiter.

That distinction is likely to become increasingly important as organizations build autonomous development pipelines.

Consulting angle

  • What objective feedback closes the agent loop? A generated artifact without executable feedback is still essentially one shot generation.
  • How is agent output independently verified? Look for tests, contracts, static analysis, coverage, runtime evidence, and deterministic quality gates.
  • Where are LLM judges being treated as authority? They can help triage and interpret results, but should not silently replace objective verification.

The broader consulting message is becoming clearer: the differentiator in an AI enabled SDLC is not simply which coding model a client uses. It is the verification architecture around the model.
