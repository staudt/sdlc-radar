Agent run seams get closed: failed state, host mounts, and traces

Back to Radar

October 19, 2026

Today's theme is the seams of an agent run: what it can write back to the host, how a failed run is reported, and whether its trace follows it across tools, which decides whether an agent can alter your files or repeat an action without anyone noticing.

Main signal

Agent tooling is closing the gaps at the edges of a run, not only inside it. Claude Code now marks a scheduled run that died as Failed and stops rerunning half-finished work, Inspect AI blocks writable host mounts and no longer unpacks agent-controlled archives on the host, and Goose passes W3C trace context from the editor prompt into MCP tool calls. A run that reports success after failing can post the same report twice, and a sandbox with a writable host mount lets the agent under test change files on the machine scoring it.

"An agent run that shows Completed after it died, or restarts from the beginning, repeats actions and hides failures."

Quick News

  • GitHub Copilot CLI 1.0.99 and 1.0.100 pre-releases (Oct 16) add a flag to turn off client telemetry uploads, update managed plugins mid-session when managed policy changes, and explain credential-proxy certificate failures in sandboxed commands.

1. Scheduled agent runs stop repeating work and report failure honestly Experiment now

Layer: evidence, orchestration

Claude Code 2.1.302 (Oct 16) no longer reruns a cloud routine that failed partway from the start an hour or more later, a rerun that could post the same report twice, and shows such runs as Failed instead of Completed. It also fixes a missing classifier_category on OpenTelemetry tool_decision events for auto mode blocks and turns fork subagents on by default in claude -p and the Agent SDK.

Why it matters: Unattended agent jobs need a true failed state and safe retries, so test that a job killed midway shows as failed and that a retry does not repeat its side effects.

2. Evaluation sandboxes stop trusting what the agent writes Experiment now

Layer: execution, verification

Inspect AI 0.3.280 (Oct 14) makes Docker sandboxes block writable host mounts by default, and 0.3.281 (Oct 15) stops Docker read_file() from unpacking agent-controlled archives on the host or filling its disk. It also rejects unknown sandbox names even when only one environment exists.

Why it matters: Files going in and coming out are an escape path, so add evaluation cases where the agent writes to a mounted folder or returns an oversized archive and confirm the host is untouched.

3. One trace now follows a prompt from the editor into the tool call Watch closely

Layer: evidence, orchestration

Goose 1.55.0 (Oct 16) passes W3C trace context from ACP prompts to MCP tool calls and surfaces provider request IDs in responses and errors. It also deletes the legacy agent loop and removes background subagents and the orchestrator.

Why it matters: A single trace across the editor, agent, and tool lets you tie a bad tool call to the prompt that caused it, but teams relying on Goose background subagents must re-test before upgrading.

Field lines

  • "An agent run that shows Completed after it died, or restarts from the beginning, repeats actions and hides failures." (Claude Code 2.1.302 release notes)
  • "An agent evaluation sandbox with a writable host mount lets the agent under test change files on the machine that scores it." (Inspect AI 0.3.280 release notes)

Bet tracker

Bet: Agent control planes will move outside the agent's own process and network reach. Strengthening. Inspect AI now refuses writable host mounts by default and will not unpack agent-controlled archives on the host, so the evaluation host is protected from what the agent produces.

Consulting angle

Ask this week: Take one scheduled agent job: if it died halfway tonight, would your dashboard show Failed, and would the retry repeat anything it already did?
