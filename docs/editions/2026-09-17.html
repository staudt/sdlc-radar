AI SDLC Radar

Today brings unusually strong production evidence for a question that has hovered over agentic development: can agents execute genuinely large software modernization work without turning quality control into guesswork?

View the current SDLC Radar

Main signal

Agentic scale is starting to come from decomposition and verification, not from giving one agent broader autonomy. GitHub's production Rust migration shows that agents can carry a very large modernization effort when the work is broken into reviewable slices, existing tests remain authoritative, static analysis supplies fast feedback, and humans operate the control loop.

1. GitHub used coding agents for an 800,000-line production Rust migration

Study closely

What changed: GitHub published a detailed engineering account of rewriting the Copilot agent runtime from TypeScript into more than 800,000 lines of production Rust. AI agents wrote most of the code across 128 merged port pull requests. The migration landed incrementally over roughly fourteen and a half weeks rather than through a big-bang cutover.

Why it matters: The important result is not the raw line count. Each port was a bounded slice. Existing end-to-end tests ran against the new Rust implementation at every step, required failures blocked merges, and production exposure happened incrementally across 135 releases. By completion, the runtime had about 468,000 lines of Rust unit tests and 174,000 lines of TypeScript end-to-end tests, with another roughly 130,000 lines of SDK end-to-end tests across six languages.

The session data is even more revealing for QA architecture. The agents executed 19,485 test commands and 23,096 compilation commands. File reading and search activity outweighed editing by roughly ten to one. GitHub's engineer describes the human role as operating the control loop: reviewing results, challenging design decisions, enforcing quality gates, and deciding when intermediate work was actually complete.

SDLC fit: large-scale modernization, language migrations, architecture refactoring, technical-debt programs, and other work that can be decomposed into independently verifiable slices.

Maturity: This is production evidence, not a benchmark. It does not prove that arbitrary large migrations can be delegated safely, but it materially raises the ceiling for agent-assisted modernization when the surrounding engineering system is strong.

2. Browser agents are growing their own policy and evidence layer

Experiment now

What changed: BetterWright is an actively developed open-source Playwright browser runtime for agents that has reached roughly 286 GitHub stars since July. It combines persistent browser sessions with compact observations, configurable network controls, credential handling, screenshots as evidence, and human handoff. It can be used through a CLI, MCP server, or JavaScript and TypeScript SDK.

Why it matters: This is a useful architectural direction beyond simply giving an agent a browser tool. Browser execution is being wrapped in explicit session state, network policy, credential boundaries, result envelopes, and evidence capture. BetterWright also documents its limitations clearly: network access is permissive by default unless restricted, its snippet sandbox is defense in depth rather than a hard security boundary, and credential filling does not make secrets inaccessible to a compromised page or host.

SDLC fit: browser-based QA agents, exploratory testing, authenticated test flows, agentic regression investigation, and controlled browser automation where a team needs stronger operational boundaries than raw Playwright access alone.

Maturity: Early but technically substantive. The project is active and gaining traction, but it should be evaluated as an experimental runtime rather than assumed to provide enterprise-grade isolation.

Emerging pattern

  • Large agentic programs become tractable when work is decomposed into small, independently verifiable changes.
  • Deterministic tests, compilers, linters, and static analysis are becoming the feedback substrate for agent reasoning.
  • Human effort is moving upward from syntax production toward architecture, quality gates, exception handling, and acceptance authority.
  • Agent tools themselves are acquiring policy, credential, evidence, and observability layers.

Consulting angle

AI readiness assessments should now ask a more demanding question than whether a team has access to coding agents. Can the codebase be changed incrementally while remaining shippable? Are tests strong enough to block incorrect slices? Are compiler and static-analysis signals fast and trustworthy? Can large modernization work be partitioned into reviewable units with clear acceptance evidence? For browser agents, also assess network boundaries, credential handling, human handoff, and proof artifacts.

For modernization programs, the GitHub case is a concrete reason to evaluate agent-assisted language migrations and large refactors now, but only where the validation harness is already strong or can be strengthened first.
