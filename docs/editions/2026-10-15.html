Agent runs need receipts, not just guardrails

Back to Radar

October 15, 2026

Today's theme is whether you can prove what an agent run actually did: which model answered, which tools it had, and what it wrote back to your repository, all of which decide whether an incident in your delivery pipeline can be investigated or only guessed at.

Main signal

Agent harnesses are adding records and integrity checks around the run itself, not only limits on it. Claude Code now stamps OpenTelemetry GenAI attributes on its traces and keeps each request's system prompt, tools, and parameters in local transcripts, while GitHub Agentic Workflows rejects silent model substitution and ties code applied from an agent to bytes that were validated first. Without these records, a bad agent change in your repository cannot be traced to the prompt, tool, or model that produced it.

"If an agent run does not record the prompt, tools, and parameters of every model call, you cannot audit it after an incident."

1. Agent traces get a standard vocabulary and a full request record Experiment now

Layer: evidence, verification

Claude Code 2.1.300 (Oct 14) adds OpenTelemetry GenAI semantic-convention attributes such as gen_ai.tool.name, gen_ai.conversation.id, and error.type to trace spans, and local transcripts now record each API request's system prompt, tools, and parameters. It also validates hook updatedInput like the tool's own input and drops unknown keys, and lets the agent.spawn hook rewrite a workflow agent's prompt and model.

Why it matters: Standard span names let one dashboard compare agents across vendors, but a hook that can rewrite a workflow agent's prompt or model is a control you must test and log, so confirm the trace shows the final prompt and model, not the original.

2. Agent workflows start rejecting silent model swaps and unvalidated patches Experiment now

Layer: policy, evidence

GitHub Agentic Workflows v0.92.0 (Oct 15, pre-release) makes Copilot reject silent substitution of the configured model and binds safe-output patch and bundle application to validated bytes. v0.91.14 (Oct 14) keeps GH_AW_OTLP_ALL_HEADERS out of agent and eval sandboxes and masks decoded credentials in artifacts and step summaries, and the notes advise recompiling workflows.

Why it matters: If the model or the applied patch can differ from what was approved, test results and review no longer describe what shipped, so add a check that the model recorded in the run matches the model configured and that applied changes match the reviewed diff.

3. Plugin failures stop being silent in a coding agent Watch closely

Layer: execution, policy

Cline's SDK v0.0.93 (Oct 13) loads plugins in-process through one registry, offers a subprocess sandbox with CLINE_PLUGIN_MODE=sandbox, and reports plugin failures with status and errors instead of silently dropping tools. Extension v4.1.24 also stops an MCP server or hook that exits early from crashing the extension host.

Why it matters: An agent missing a tool it was meant to have behaves differently without telling anyone, so assert the expected tool list at the start of every run, and prefer the sandboxed plugin mode for third-party plugins.

Field lines

  • "If an agent run does not record the prompt, tools, and parameters of every model call, you cannot audit it after an incident." (Claude Code 2.1.300 release notes)
  • "A workflow that silently swaps the configured model changes your test results without anyone approving it." (GitHub Agentic Workflows v0.92.0)
  • "An agent plugin that fails without an error means your agent is running with fewer tools than you think." (Cline SDK v0.0.93 release notes)

Bet tracker

Bet: Agent control planes will move outside the agent's own process and network reach. Strengthening. gh-aw now keeps telemetry credentials out of agent sandboxes and binds applied patches to validated bytes, so the enforcement sits outside what the agent can edit.

Bet: Cost, model strength, and independent verification will be optimized together at runtime through workflow routing. Strengthening. Rejecting silent model substitution and the agent.spawn hook that rewrites a workflow agent's model make routing a controlled, loggable decision.

Consulting angle

Ask this week: For your last agent-written change, can you show which model, system prompt, and tool list produced it, and would a silent model swap or a missing plugin have appeared in the record?
