Who a coding agent answers to: proactive agents, layered gateway policy, and snapshot-checked desktop control

Back to Radar

November 2, 2026

Today's theme is what authorizes a coding agent's next action: a proactive agent that opens work on its own, a gateway that merges several policies and shares one budget, and desktop control that refuses stale references, which decides whether your repositories, spend, and test runs act on a request someone actually approved.

Main signal

Agent actions are being tied to a named requester, a merged policy, and a fresh snapshot instead of to a prompt. DeepSeek's dsh-superagent prototype opens a work item only when an allowed person asks or a team-written rule permits, Claude Code 2.1.316 adds layered gateway policy and pooled group budgets, and Agent Desktop 1.0 rejects a desktop action whose element reference came from an older snapshot. An agent that acts with no traceable request, or on a screen that has changed, can open pull requests nobody asked for or click the wrong control.

"An agent that acts on its own needs a named requester or a written rule behind every action, and a record of which one applied."

1. DeepSeek publishes a proactive coding agent that decides when to act Watch closely

Layer: orchestration, policy

DeepSeek released dsh-superagent (MIT), which Bloomberg reported on Nov 1 as a challenger to Claude Code. Its README says it watches GitHub and optionally Feishu, opens a work item when an allowed person asks or a team-written rule permits, runs each item in its own session and directory, and reports back, for example with a pull request, plus a web panel for items that need a person. The authors call it a research prototype that is not production-ready, say the public version differs from the design article, and I read the README, not the authorization document or the Bloomberg article.

Why it matters: A harness that starts work unprompted moves the approval question from "who reviewed this output" to "who allowed this to start", so require a log of which request or rule triggered each work item.

2. Claude Code's gateway merges policies and pools budgets Experiment now

Layer: policy, evidence

Claude Code 2.1.316 (Oct 31) adds policy_mode: layered, which applies every matching gateway policy merged over the ones below it, and pooled_budget for shared group spend limits. The gateway now checks every requested model against availableModels, deniedModels, and models, and server-managed settings for Team and Enterprise logins apply without an approval prompt while a stored copy that fails verification is refused.

Why it matters: A developer in several groups now gets a merged rule that no single policy file shows, so test one such user and confirm which model and budget apply and that a tampered stored settings copy is refused.

3. Desktop control for agents starts rejecting stale references Experiment now

Layer: execution, verification

Agent Desktop (v1.0.0 Oct 28 to v1.0.2 Oct 30) is a CLI and C library for macOS, Windows, and Linux that reads each app's accessibility tree instead of screenshots and hands the agent a reference for each element. A reference is tied to its snapshot, a bare reference is rejected, and a changed UI returns STALE_REF or AMBIGUOUS_TARGET so the agent must re-snapshot; the project warns that snapshots, clipboard reads, and screenshots can contain private content. I read the project page and release list, not the code.

Why it matters: Failing loudly on a stale reference gives native-app test automation a behavior that coordinate clicking lacks, so trial it on one native flow and keep its snapshots out of shared logs.

Field lines

  • "A proactive coding agent is only governable if every work item records the request or rule that started it." (dsh-superagent README)
  • "When agent policy is merged from several layers, test the effective rule a developer ends up with, because no single policy file shows it." (Claude Code 2.1.316 release notes)
  • "Desktop test automation that rejects a stale element reference fails loudly instead of clicking the wrong control." (Agent Desktop project page)

Bet tracker

Strengthening: Agent control planes will move outside the agent's own process and network reach. Claude Code's gateway now merges layered policy and pools budgets at the gateway, outside the agent process (Claude Code 2.1.316).

Consulting angle

Ask this week: For every agent action that starts without a developer typing a prompt, whether scheduled, proactive, or triggered from chat, can you show which request or rule allowed it and which policy and budget applied?
