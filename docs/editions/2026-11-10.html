Permission checks that missed: sandbox gaps, vanishing hooks, and redirected tokens

Back to Radar

November 10, 2026

Today's theme is holes in the permission layer of coding agents: Claude Code 2.1.321, its Agent SDK 0.3.321, and Copilot CLI 1.0.108 and 1.0.109 fix commands that ran outside the sandbox, deny rules that missed file writes, hooks that vanished, and sign-in tokens that could be sent to the wrong host, which decides whether the rules you wrote actually stop an agent working on your source code and credentials.

Main signal

The controls that gate an agent are being found to have gaps in the paths they cover, not only in their settings. Claude Code 2.1.321 (Nov 9) fixes a read-only Bash command that could run outside the sandbox with no prompt and deny rules that did not apply to the file cp or mv writes. Its Agent SDK 0.3.321 fixes a bug that dropped every hook when one hook event was set to undefined. A rule that exists but misses one write path, or a hook that silently disappears, lets an agent change files and use credentials with nobody having said yes.

"A deny rule only protects the paths it covers, so test every way an agent can write a file, not just the rule text."

1. Claude Code 2.1.321 closes sandbox and deny-rule gaps Production now

Layer: policy, execution

Claude Code 2.1.321 (Nov 9) fixes a read-only Bash command that could run outside the sandbox without a permission prompt, a file write judged against the wrong folder so the prompt was skipped, and deny rules and protected-file prompts that did not apply to the file cp or mv writes into a directory. On Linux, claude -p now prints an error and exits 1 when NFS loses transcript lines, which the 2.1.317 notes had listed as a remaining gap. I read the release notes, not the code.

Why it matters: Upgrade, then add tests that try a write to a denied path through cp, mv, and a redirect, because a deny rule that missed those on earlier builds means your audit of past agent runs may also have missed them.

2. Hooks and MCP sign-in tokens had silent failure paths Experiment now

Layer: policy, evidence

Claude Code 2.1.321 fixes a PreToolUse hook's ask being lost when another hook's defer finished first, and an MCP OAuth refresh token that could be sent to another host if a server redirected the request. A PreToolUse mcp_tool hook whose output exceeds 16 MiB now causes the tool call to be refused instead of the hook being skipped. Agent SDK 0.3.321 (Nov 9) fixes every hook being dropped when one event in the hooks option is undefined, and a wrong hook reason reported when two hooks both asked.

Why it matters: Add a startup check that an enforcement hook actually fired on a known risky call, and rotate MCP refresh tokens for servers that redirect, because a missing hook produced no error.

3. Copilot CLI makes fewer read-only prompts but always reviews ref changes Experiment now

Layer: policy, execution

Copilot CLI 1.0.109-0 (Nov 9, pre-release) prompts less often for read-only shell scripts while always reviewing scripts that change git refs or read through hidden paths, and asks before /share and /export follow symlinks. Version 1.0.108 became the stable build on Nov 9, and 1.0.109-1 (Nov 10) adds IPv4 and IPv6 CIDR ranges to sandbox host allow and deny rules. These are mostly pre-releases and I read the release notes, not the code, so how it decides a script is read-only is unverified.

Why it matters: Fewer prompts is only safe if the read-only check is right, so feed it scripts that look read-only but change refs or follow symlinks and confirm each still prompts.

Field lines

  • "A deny rule only protects the paths it covers, so test every way an agent can write a file, not just the rule text." (Claude Code 2.1.321 release notes)
  • "A security hook that silently disappears leaves an agent running with no policy check and no error, so prove each enforcement hook fires." (Claude Agent SDK 0.3.321 release notes)
  • "Cutting permission prompts for read-only shell scripts is safe only while the check that decides read-only holds up against scripts that change git refs." (Copilot CLI 1.0.109-0 release notes)

Bet tracker

Strengthening: Agent control planes will move outside the agent's own process and network reach. Claude Code 2.1.321 fixed a Bash command that ran outside the sandbox with no prompt and deny rules that skipped cp and mv targets, while Copilot CLI 1.0.109-1 adds network ranges to sandbox host rules, so checks inside the session keep needing patches and the enforced boundary sits around it (Claude Code 2.1.321, Copilot CLI 1.0.109-1).

Consulting angle

Ask this week: Which ways can your coding agent write a file (shell redirect, cp, mv, editor tool), which of them does your deny list not reach, and which test proves each one is blocked?
