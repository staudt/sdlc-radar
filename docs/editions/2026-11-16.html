Signals

GovernanceProduction now

Coding-agent session logs are now a breach path, because the credentials developers type end up stored in them.

Cursor's incident update on Nov 13 traces its October breach to a Cursor access key exposed at inference provider Fireworks AI (MLQ, GBHackers). The attacker used it to copy a bucket Cursor shared with Fireworks. It held coding-agent traces from sessions outside Privacy Mode that Cursor could use for training. Some traces contained unredacted credentials, which opened several internal Cursor tools and, from there, its extension marketplace cache.

The chain ended in tampered builds 2.1.312 and 2.1.313 of the Claude Code extension, live on Cursor's marketplace for about 11 hours on Oct 29, which planted an attacker SSH key on up to 5,000 machines (Dark Reading). Cursor says fewer than 0.05% of users had traces exposed, last saw attacker activity Nov 1, moved all inference off Fireworks and extended secret scanning to internal data sources. Figures and the attribution are Cursor's; Fireworks has not confirmed them.

Fireworks also disclosed a second, separate breach through a cloud provider, and Notion told customers that AI chat transcripts from fewer than 1% of workspaces may be exposed (BleepingComputer, eSecurityPlanet).

Why it matters: Last week's leak sat in repository files. This one sat in session data held by a vendor, where no repository scan reaches. Every copy of an agent session needs redaction before it leaves and a secret scan where it lands.

"Coding-agent session logs keep the passwords developers type, so any copy shared with a vendor is a credential store and needs the same controls."
Cursor incident update, via MLQ and GBHackers, Nov 13, 2026

GovernanceProduction now

Agent harnesses stop trusting configuration and code that arrive with the repository.

Codex 0.169.0 (Nov 13) keeps project configuration and MCP servers off for codex exec in untrusted directories, even with workspace write access, until --trust is passed. Claude Code 2.1.325 (Nov 13) fixes a committed .claude/settings.local.json being treated as the user's own settings, and an allow rule that could run a different program than the one it names. GitHub Agentic Workflows v1.2.3 (Nov 13) and v1.3.0 (Nov 16, pre-release) admit only same-repository pull requests to pull_request_target by default, require pinned checksums for the agent CLIs they download, and can block publishing after a failed agent job.

Why it matters: A cloned repository or a fork pull request is untrusted input to the agent. Add a CI test that runs the agent on a repo carrying hostile agent settings and confirms they are ignored.

"A coding agent should ignore settings and tools that arrive inside a repository until someone trusts that repository on purpose."
Codex 0.169.0, Claude Code 2.1.325 and GitHub Agentic Workflows v1.2.3 release notes, Nov 13, 2026

QA and testingExperiment now

Security testing agents are being paired with an evidence log they cannot edit.

Detectify launched Agentic Tooling on Nov 16 (SiliconANGLE, product page). The customer's own agent, such as Claude Code, connects over MCP and tests each finding against the running application with Detectify's attack tooling. Every request lands in a Security Ledger that Detectify writes and the agent cannot edit. Findings that could cause harm, such as denial of service, are marked Unsafe and left for a person. Claims are vendor-reported, with no accuracy data.

Why it matters: An agent's "confirmed" is a claim until the traffic behind it is on record. Ask for the same split in any agent QA tool: the agent acts, an independent component records.

"A finding from an AI testing agent counts only when the requests behind it sit in a log the agent cannot edit."
Detectify Agentic Tooling launch, Nov 16, 2026

Also in the news

  • Act Google's Jules coding agent has been read-only since Nov 11 and shuts down Dec 31; export memories and settings before then.
  • Claude Code 2.1.325 (Nov 13) also fixes deny rules that missed some Bash commands and compound commands that ran without asking.
  • Copilot CLI 1.0.112 (Nov 13, stable) adds regex to enterprise shell permission rules and turns off the built-in GitHub MCP server when org policy disables MCP.

Bets

StrengtheningAgent working folders (approvals, memory, transcripts) will become a standard target for secret scanning and audit, like CI configuration.

StrengtheningAgent control planes will move outside the agent's own process and network reach.

Ask a client today

Which vendors keep copies of your developers' coding-agent sessions, and has anyone scanned those copies for the credentials typed into them?
