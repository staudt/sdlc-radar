Agent permissions get enforced earlier and logged per action

Back to Radar

October 16, 2026

Today's theme is how agent permissions are enforced and recorded at the moment of each action, whether a network request, a resumed session, or a tool call, which decides whether leaked source code or credentials can be traced and whether a failed agent run can be diagnosed instead of simply re-run.

Main signal

Permission decisions are moving from setup-time configuration to checks and records made at every action. Codex now checks network permission before it resolves a hostname and restores a resumed session's approvals, while Claude Code logs the permission mode and classifier verdict on each tool decision. Without both, an agent can reach a host nobody approved, and you cannot later show why an action was allowed.

"An agent permission that is not checked before the request and not written to the run log is one you can neither trust nor audit."

1. Network and approval checks move earlier in the Codex run Experiment now

Layer: policy, execution

Codex 0.163.0 (Oct 15) has its network proxy check permission before a DNS lookup, rejects duplicate Host headers, and stops brokered credential aliases from bypassing inspection hooks. It also runs sandbox integrity checks before commands and filesystem operations, and resuming a saved thread restores its permissions and network approvals.

Why it matters: Egress rules that act after name resolution, or approvals lost on resume, leave gaps, so test that a blocked host is refused before any lookup and that a resumed session has no more access than the original.

2. Permission decisions become telemetry in Claude Code Experiment now

Layer: evidence, policy

Claude Code 2.1.301 (Oct 15) adds classifier_verdict and permission_mode to OpenTelemetry tool_decision events, and adds a retry watchdog setting so unattended runs can end a request when a usage limit resets too far away.

Why it matters: After an incident the question is why an action was allowed, so confirm your collector keeps these fields and alert on actions allowed under a permissive mode.

3. Failed agent workflow runs become clusterable and replayable Watch closely

Layer: evidence, verification

GitHub Agentic Workflows v0.92.1 (Oct 15) adds failure clustering and investigation plans to its logs and artifact replay, with no further detail in the notes. v0.92.2 (Oct 16) bumps the bundled engines to Copilot CLI 1.0.98, Codex 0.163.0, Gemini CLI 0.64.0, Goose 1.54.0, and Kiro CLI 2.31.1.

Why it matters: Grouped failures and replay make agent incidents diagnosable, and because one release moves five agent engines at once, record the engine versions of every run so a behavior change can be tied to an upgrade.

Bet tracker

Bet: Agent control planes will move outside the agent's own process and network reach. Strengthening. Codex's proxy now decides before DNS resolution and verifies sandbox integrity before commands, so enforcement runs ahead of anything the agent does.
