Longer agent runs shift the burden to review and evidence

Back to Radar

October 5, 2026

Today's signal is about the length of agent runs: sessions are getting longer and touching more files, which raises the value of checkpoints, independent review, and quality gates beyond passing tests.

Main signal

Longer agent runs shift the burden from generation to review and evidence. Sessions are lasting minutes instead of seconds, harnesses are adding built-in reviewers and fallback paths, and the code agents leave behind is starting to show maintainability debt.

"The longer the agent runs, the more the harness has to remember and the more the reviewer has to check."

1. Agent sessions get longer and touch more files Watch closely

Layer: orchestration, evidence

Anthropic's agentic coding trends data, summarized here, reports average coding sessions growing from 4 to 23 minutes and multi-file editing rising from 34% to 78%.

Why it matters: Longer, wider runs need resumable checkpoints and per-step evidence, because a single end-of-run diff is too large to review.

2. Reviewer and fallback become built-in harness features Experiment now

Layer: verification, orchestration

Claude Code 2.1.288 adds a built-in reviewer to every session and an automatic fallback to a backup model when the primary is unavailable, per the release notes.

Why it matters: Test the fallback path and the reviewer's independence, because a silent model swap changes both behavior and the evidence you can rely on.

3. Agent-written code starts to decay long-lived codebases Experiment now

Layer: verification

Sourcegraph's CEO told the AI Engineer World's Fair that agents are producing a tidal wave of code, with duplication, drifting standards, and brittle dependencies accumulating in decades-old codebases.

Why it matters: Acceptance gates need maintainability checks such as duplication and dependency drift, not only green tests.

Field lines

  • "A green test suite tells you the change works. It does not tell you the codebase is healthier." (Sourcegraph via AI Brief)
  • "If the fallback model reviews its own work, you do not have a reviewer." (Claude Code release notes)

Emerging pattern

Run length, reviewer design, and code health are one problem: how much unreviewed change an agent can accumulate before someone with evidence looks at it.

Consulting angle

Ask this week: What is the largest unreviewed change an agent can produce in one run, and what checkpoint or gate stops it from growing?
