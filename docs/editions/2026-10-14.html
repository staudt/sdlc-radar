The harness is the thing to evaluate

Back to Radar

October 14, 2026

Today's theme is the agent harness as the thing you buy and test, not the model: where parallel agents run, how much the harness changes results, and how to test the tools websites now expose to agents, all of which decide whether your delivery quality depends on a vendor's demo or on your own evidence.

Main signal

The harness, not the model, is becoming the unit that has to be evaluated. Meta is gating its strongest coding model behind its own agent product, and a new 300-task benchmark finds the same models score several points apart depending on which harness runs them. A team that picks a model from a leaderboard can therefore ship an agent that fails on its own code.

"The same model scores differently in different agent harnesses, so test the harness on your own tasks, not the model on a leaderboard."

Quick News

  • Meta Muse Wonder (Oct 12) is Meta's first frontier model, priced like Claude Opus 5.5 at $4 and $20 per million tokens, with vendor-reported coding scores that outside indexes have not yet confirmed.

1. Parallel coding agents get isolated worktrees and a bundled model Watch closely

Layer: orchestration, execution

Meta's Muse Code splits large jobs across parallel subagents, each in its own git worktree, and the strongest model, Muse Wonder Full, is available only to Muse Code subscribers. One review notes an OS sandbox and approvals are on from the first run, while another analysis says child agents share the lead's workspace unless worktree isolation is enabled.

Why it matters: When parallel agents write to one working copy they can overwrite each other, so confirm isolation is on and test that two agents editing the same file cannot collide.

2. The harness changes benchmark results Experiment now

Layer: verification, orchestration

CheckerBench (arXiv 2610.07557, submitted Oct 6) asks agents to write static-analysis checkers from 300 real vulnerability tasks, and AI Weekly's summary reports a best score of 45.33% and mean pass rates of 36.95% under OpenCode, 33.81% under Claude Code, and 26.14% under Hermes Agent. The per-harness figures come from that secondary summary, so check them against the paper.

Why it matters: A harness swap can move results by more than a model upgrade, so run your own task set through each candidate harness before standardizing.

3. Websites start exposing tools that tests must call Experiment now

Layer: verification, execution

Playwright 1.64 (Oct 7, per TestDino) adds page.webmcp and frame.webmcp to list and call the tools a page registers for agents, and Playwright MCP offers them to agents by default. The browser API is experimental and needs a Chromium flag.

Why it matters: If your product registers tools for agents, they are a user interface nobody is testing, so add a contract test that lists and calls each one.

Field lines

  • "The same model scores differently in different agent harnesses, so test the harness on your own tasks, not the model on a leaderboard." (AI Weekly on CheckerBench)
  • "Parallel coding agents need their own isolated working copies, or one agent's edits can overwrite another's." (Runtime Wire on Meta Muse Code)

Consulting angle

Ask this week: Which agent harness does your team run today, and have you measured it against your own tasks, or only against a vendor's published scores?
