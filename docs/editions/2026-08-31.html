AI SDLC Radar

A focused briefing on AI software development, modern SDLC practices, QA, test automation, and agentic engineering.

Main signal

Agentic software engineering is moving from simple autonomous execution toward governed, measurable, coordinated systems. The interesting work is increasingly about controlling when agents run, limiting how long they run, measuring how they behave, and coordinating multiple agents safely.

Agent execution + runtime controls + behavioral evaluation + independent verification

1. GitHub Agentic Workflows adds runtime gating and trajectory graders

Experiment now

GitHub's August 31 Agentic Workflows update adds several primitives that look increasingly enterprise ready. The new on.cooldown option prevents repeated triggers from piling up on the same target, while on.stop-after can use GitHub Actions expressions to bound runs dynamically.

More important for QA and governance, the project is building a trajectory grader library. Recent additions include event entropy, trajectory complexity, policy near misses, exploration error, and exploitation error. This is a shift from evaluating only the final artifact toward evaluating how the agent behaved while producing it.

Why it matters: a green pipeline can tell you whether the result passed checks. It does not tell you whether the agent behaved recklessly, looped inefficiently, nearly violated policy, or converged for the wrong reasons. Trajectory metrics provide a second quality layer.

2. ESLint Refiner shows what a useful narrow QA agent looks like

Prototype now

GitHub highlighted an internal autonomous workflow called ESLint Refiner that continuously audits the quality of custom lint rules themselves. It reviews a small number of underexamined rules, checks them against real call sites, and only files issues when it can ground the finding in actual repository evidence.

Recent runs found both misleading rule messaging and an incorrectly narrow literal classification. More interestingly, the agent also detected that a previous fix had not propagated consistently across sibling rules.

Why it matters for QA: this is a strong pattern for autonomous quality engineering because the scope is narrow, the evidence is inspectable, false positives are constrained, and the workflow continuously checks consistency across a changing codebase.

3. AgentRoom suggests coordination matters more than raw multi agent parallelism

Study closely

AgentRoom is a research system for concurrent coding agents that share a CRDT backed workspace. Agents can claim files, broadcast status, and coordinate through MCP tools while working in parallel.

The most useful result is not simply that multiple agents can work at once. The authors report that coordination itself was the key contributor. Parallel agents without the coordination layer did not show the same benefit, while coordinated agents reduced task abandonment and run to run variation on the tested workloads.

QA implication: the same principle applies to multi agent testing. A planner, generator, browser explorer, and healer need explicit contracts and shared state, not just separate prompts.

Emerging architecture

  • Bound agent runs with cooldowns, stop conditions, and deterministic execution limits.
  • Evaluate trajectories, not only final outputs.
  • Prefer narrow autonomous quality agents with evidence based findings.
  • Coordinate parallel agents explicitly with ownership and shared state.
  • Keep deterministic verification underneath so agent behavior cannot redefine success criteria.

Consulting angle

  • Are autonomous runs rate limited and bounded?
  • Can you reconstruct why an agent made a change?
  • Do you measure agent behavior as well as task success?
  • Are autonomous quality checks narrow enough to produce trustworthy evidence?
  • Can multiple agents coordinate ownership without editing the same scope blindly?
  • Are final acceptance criteria independent from the agent that generated the change?

The near term consulting opportunity is becoming agent governance plus verification architecture, not simply AI tool adoption.
