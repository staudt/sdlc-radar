Sandbox gaps get closed, remote MCP servers stay untrusted, and verification moves before the PR

Back to Radar

October 23, 2026

Today's theme is whether the limits on a coding agent actually hold: a sandbox that let shell startup files and background commands run outside it, a sign-in flow that let a remote MCP server run commands on a developer's Windows machine, and a vendor pitch to verify agent code before the pull request, which decides whether your files, credentials, and releases stay inside the boundary you think you set.

Main signal

The sandbox you configured is not always the sandbox you get. Claude Code 2.1.309 fixes cases where sandboxed shell commands ran startup files outside the sandbox, write denies lifted when a background command outlived the session, and sandboxed commands could edit the MCP config file. OpenCode shipped a fix for a critical remote code execution flaw in MCP sign-in without a CVE or advisory, so scanners will not flag the old versions. An agent that can write where you denied it, or run code from a server you connected to, can change files and reach credentials without a single permission prompt.

"A sandbox is only a control if you test it with commands that try to escape it."

1. Claude Code closes sandbox and permission gaps in 2.1.309 Production now

Layer: execution, policy

Claude Code 2.1.309 (Oct 22) fixes sandboxed Bash commands running the shell's startup files outside the sandbox, macOS denyWrite globs not applying through symlinks, Linux write denies lifting when a background command outlived the session, and sandboxed commands or auto-accepted edits being able to modify the --mcp-config file. It also fixes several Bash and PowerShell permission checks that did not prompt, and PowerShell hooks that did not block on exit code 2.

Why it matters: Upgrade any pipeline that relies on the sandbox, then re-run your negative tests: a write to a denied path through a symlink, a background process that outlives the job, and an edit to the MCP config.

2. A testing vendor ships a harness that checks agent code before the pull request Watch closely

Layer: verification, orchestration

mabl introduced an agentic testing harness (Oct 21, per RuntimeWire) that sets rules for coding agents, uses a knowledge graph to find the tests that cover a change and the gaps they leave, and shows a change's impact from the terminal before a pull request opens. The company's press release is the primary source; I could not open either page, and the accuracy and savings figures are the vendor's own.

Why it matters: Test-impact analysis before the pull request is the verification layer agent-heavy teams are missing, but test the vendor's coverage-gap findings against a change you already know the answer to before trusting them.

3. A remote MCP server could run commands during OpenCode sign-in Experiment now

Layer: policy, execution

Pillar Security's report (Oct 19), covered this week by Infosecurity Magazine and The Hacker News, describes a critical remote code execution flaw, rated 9.8, in OpenCode 1.0.137 through 1.18.32 on Windows and WSL, where an endpoint supplied by a remote MCP server during OAuth sign-in reached PowerShell unescaped. The vendor called malicious MCP servers outside its threat model, fixed it in 1.18.33 on Sep 28, and issued no CVE or advisory; I read the coverage, not Pillar's original report.

Why it matters: A fix without a CVE will not appear in dependency scanners, so inventory the agent CLI versions on developer machines and connect only remote MCP servers you control.

Field lines

  • "A sandbox is only a control if you test it with commands that try to escape it." (Claude Code 2.1.309 release notes)
  • "A remote MCP server you connect to is code you are choosing to trust, so a coding agent's sign-in flow is part of your security perimeter." (Infosecurity Magazine on the OpenCode flaw)
  • "Test-impact analysis before the pull request tells you which tests cover an agent's change, but only if the vendor's coverage claims survive a test you already know the answer to." (RuntimeWire on mabl)

Bet tracker

Bet: Agent control planes will move outside the agent's own process and network reach. Strengthening. Claude Code 2.1.309 closes paths by which sandboxed commands could edit the MCP config file passed with --mcp-config, and gh-aw v0.93.1 isolates hosted threat detection from the agent job.

Consulting angle

Ask this week: For every agent CLI in your pipeline, can you list the installed version and show a test where a sandboxed command tries to write outside its allowed paths and fails?
