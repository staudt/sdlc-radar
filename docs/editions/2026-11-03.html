When an agent run breaks: failing hooks that block, lost transcripts that fail the job, and reruns of only the failures

Back to Radar

November 3, 2026

Today's theme is how a coding agent run reports its own failures: Claude Code hook callbacks that can now block an action when they crash, a headless run that exits 1 when its transcript is lost, and a Copilot CLI depth marker for sessions launched by hooks, which decides whether your pipelines show green for runs that lost their evidence or looped on their own hooks.

Main signal

Failure paths in the agent harness are being changed from silent to loud. Claude Code 2.1.317 lets SDK hook callbacks block the action when they fail and makes claude -p exit 1, not 0, when a full disk or quota drops the transcript, after 2.1.316 marked cloud sessions failed when auto mode returned no safety verdict. A job that exits 0 after losing its audit trail, or runs an action after its policy callback crashed, reports success without the proof behind it.

"An agent run that loses its transcript or its policy check and still exits zero is reporting success without evidence."

1. Claude Code makes lost evidence and failed hook callbacks stop the run Experiment now

Layer: evidence, policy

Claude Code 2.1.317 (Nov 3) lets Agent SDK hook callbacks set onFailure: "block", so a failing callback blocks the action instead of letting it run. It also makes claude -p print an error and exit 1 when a full disk or quota drops transcript or ~/.claude.json writes, where it used to exit 0, though the notes say NFS exports may still be missed. Version 2.1.316 (Oct 31) already marks cloud sessions and scheduled tasks failed when auto mode stops a turn because the server returned no safety verdict.

Why it matters: Set onFailure: "block" on callbacks that enforce policy, and add a negative test with an unwritable transcript path, because pipelines that tolerated exit 0 may now fail and the ones that cannot fail still pass without evidence.

2. Copilot CLI gives hooks a depth counter and keeps user-only MCP content from the model Watch closely

Layer: orchestration, policy

The GitHub Copilot CLI 1.0.106 pre-releases (Nov 2 to Nov 3) pass COPILOT_HOOK_DEPTH to command hooks so a session launched by a hook can stop recursive agentStop chains, and stop sending MCP content addressed only to the user to the model. They also stop removed repository hook configs from blocking later tool calls in the same session. These are pre-releases and I read the release notes, not the code.

Why it matters: A hook that starts an agent can start another when that one stops, so cap depth in your own hook scripts now, and decide which MCP output may reach the model before these builds become stable.

3. Vitest 5.1.0 lets an agent rerun only the tests that failed Experiment now

Layer: verification

Vitest 5.1.0 (Nov 2) adds --last-failed to rerun only failed tests and --since-last-run, shows each attempt of a retried test in error logs, and makes the trace view show failures only by default. It also reruns setup files after --changed filtering.

Why it matters: A failed-only rerun is a cheap repair loop for an agent but a green result there says nothing about the other tests, so keep the full suite as the merge gate and have the agent report which command produced its green.

Field lines

  • "An agent run that loses its transcript or its policy check and still exits zero is reporting success without evidence." (Claude Code 2.1.317 release notes)
  • "A hook that can launch an agent session needs a depth limit, or one stop event can start an unbounded chain of agent runs." (Copilot CLI 1.0.106 release notes)
  • "A green rerun of only the failed tests is a repair signal, not an acceptance result, so the full suite still decides whether code merges." (Vitest 5.1.0 release notes)

Bet tracker

Strengthening: Agent control planes will move outside the agent's own process and network reach. Claude Code 2.1.317 stops offering "don't ask again" on mod tool calls for Remote Control and SDK hosts, so the host, not the agent session, decides what stays approved (Claude Code 2.1.317).
