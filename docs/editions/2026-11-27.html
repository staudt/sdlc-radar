Signals

QA and testingExperiment now

Agent-written tests now look thorough by every usual measure and still miss most bugs, so acceptance has to move to bug-finding.

SpecEngineeringBench, a preprint submitted Nov 24 (arXiv 2611.32973), gave seven coding agents a requirements document and a Python repository, across 100 tasks from 78 projects, and asked for tests and defect reports. The tests passed 91% of the time and covered 80% of the changed code. Only 26% exposed the seeded defect.

Two other studies point the same way. A Microsoft preprint (arXiv 2611.34875) finds agent patches on SWE-bench Verified change a median of 2.33 times more lines than developers' patches, and 61% of the extra lines are tests. A NeurIPS 2026 paper (NeurIPS) finds Claude Code, Codex and Cursor beat human-written suites on coverage, largely by writing more tests rather than stronger ones.

It matches Thursday's Rust port, which passed 98% of its tests but matched 24% of production inputs (Thursday). These are research results, not field data.

Why it matters: Coverage and pass rate now measure how much an agent wrote. Accept agent tests on whether they fail when the code is wrong: mutation score or seeded defects.

"Coverage tells you how much test code an AI agent wrote, not whether it catches bugs. Accept agent-written tests only when they fail against deliberately broken code."
SpecEngineeringBench, arXiv 2611.32973, Nov 24, 2026; Microsoft over-edit study, arXiv 2611.34875

Engineering flowExperiment now

About one in nine code units in an agent's patch is not needed, and most of those change behavior.

The same Microsoft preprint (arXiv 2611.34875) traced 7,660 resolved GitHub Copilot CLI runs across 18 models to see where unneeded edits come from. About 11% of the code units in an agent's patch were not needed for the fix, and 89% of those still change behavior. 83% were written during fix steps, while debugging steps added almost none. On production code, 11 of the 18 models left less unneeded code than the human developers did. The data is Python only.

Why it matters: Reviewers check that a fix works, not that every line is needed, and unneeded lines that change behavior are where surprises hide. Strip edits the tests do not need before review, with a minimization step in the pipeline.

"An AI agent's fix often carries extra code that changes behavior. Remove what the tests do not need before a person reviews it, so review covers only the real change."
Microsoft, How Much Do Coding Agents Over-Edit, and Why?, arXiv 2611.34875, Nov 2026

GovernanceExperiment now

Platforms now make AI agents connect as agents, with their own client IDs, scopes and quotas.

Google said this week that AI agents must reach Workspace data through its Workspace MCP servers or CLI rather than the REST APIs, with enforcement from Feb 1, 2027 (Google Workspace blog, Machine Herald, Nov 26). External agents need dedicated OAuth client IDs with least-privilege scopes and usage quotas, with billing from April 1, 2027. SailPoint's Nov 27 outlook repeats its survey finding that 79% of enterprises run agents in production and 2% have identity controls built for them (Help Net Security); the figures are SailPoint's.

Why it matters: Agents riding on an app's or a person's credentials will have to move, and that is the point: a separate identity makes agent actions visible and revocable. Inventory which Workspace integrations are agents before February.

"Google will soon tell AI agents apart from apps at the door. Give every agent its own credentials, scopes and limits now, so you can see what it does and switch it off."
Google Workspace announcement via Machine Herald, Nov 26, 2026
