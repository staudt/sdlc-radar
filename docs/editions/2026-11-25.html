Signals

GovernanceExperiment now

What coding agents read is now the attack path: search results and skills, not only packages.

AIR Research Lab's WebSec Benchmark, described in The Hacker News on Nov 23, ran about 37,700 coding-agent searches. 534 surfaced known-malicious content, including packages one letter off popular libraries, impersonating repositories and install steps for packages never published. The figures are AIR's.

AIR's earlier Web Hole study shows one route in: across about 2,000 queries, 36 results pointed to lapsed domains anyone could buy while the result keeps its rank.

Meanwhile Claude Code 2.1.332 lets MCP servers supply skills (beta) and adds a PreSkillShellCommand hook that can refuse a skill's inline shell commands as it loads (changelog). With OX's findings on poisoned tool descriptions (Tuesday), the text an agent reads is now part of the supply chain.

Why it matters: A search result can now become an installed package. Allowlist agent search and installs, verify packages before install, and block shell commands from unreviewed skills.

"Your coding agent installs what its search results tell it to. Treat those results as untrusted input: allow known sources and registries, and verify every package before install."
AIR Research Lab WebSec Benchmark, via The Hacker News, Nov 23, 2026; Claude Code 2.1.332 changelog

QA and testingWatch closely

Coding agents sometimes "fix" a rule violation by deleting the feature, and an external checker changes the outcome.

A new preprint planted 31 defects in 25 pull requests across ten open-source projects and asked three agents to repair them (arXiv 2611.29162). Nine free static-analysis tools together caught 8 of the 31. Findings from the commercial CodeAssure checker raised repair rates by 43 to 48 points, to between 69% and 93%, counting only repairs that compile and keep the feature. The medium model with findings beat the largest model alone, 90% to 45%, at a fifth of the cost. The author is affiliated with CodeAssure Labs, which sells the checker.

Why it matters: A green build after an agent repair can mean the feature is gone. Score deletions as failures, and feed agents findings from a checker they do not control.

"When an AI agent fixes a defect, check that the feature still exists. Deleting the code makes the warning go away too."
arXiv 2611.29162 preprint, Nov 2026

Engineering flowWatch closely

Agents now write security mitigations that load into running production systems, as signed code that people approve.

OpenAI and Cisco released Shirudo on Nov 23, an open-source Linux runtime that loads temporary eBPF "shields" to block an exploit until a patch lands, without restarting services (OpenAI, SecurityWeek, MarkTechPost). Agents write and test the shield; security teams decide what deploys, and shields are signed and verified before loading. In a controlled test, a Codex-written shield blocked a Java4Shell exploit against a running Elasticsearch service. Coverage describes it as not yet production-ready.

Why it matters: This production change skips the release train. It needs its own tests, signing, approver and rollback first.

"An AI-written security patch that loads into a running server is still a production change. Test it, sign it, and name who approves it before the first one ships."
OpenAI and Cisco Shirudo release, Nov 23, 2026
