About

Main signal

Agent controls now have to be tested and evidenced, not just configured.

The strongest implementations still separate agent reasoning, deterministic execution, independent verification, and privileged approval. The new requirement is proof that each boundary holds: what the agent can reach, what its controls blocked, and what every run actually did. QA is becoming the function that tests the harness itself.

Current picture

Patterns that keep repeating across recent editions.

  • Testing is becoming a control system. Acceptance increasingly includes behavior, execution trajectory, policy decisions, and runtime evidence—not just pass/fail.
  • QA is moving earlier. Specification quality increasingly determines agent quality.
  • Scale comes from decomposition. Large agentic changes become credible when work is split into small, reviewable slices with deterministic acceptance evidence.
  • Agents are closing their own test loop. Observable state, controllable inputs, logs, and deterministic gates let agents implement, exercise, diagnose, repair, and retry with less human intervention.
  • Permissions are architecture. Reasoning and privileged execution need separate trust boundaries, and an agent acts on whatever it can reach: networks, credentials, stray instruction files, and the monitors that watch it. Default-deny access is replacing prompt-level restraint.
  • The harness is part of the attack surface. Plugins, hooks, MCP servers, and sandbox settings the agent can reach need the same pinning, review, and testing as application dependencies, and a sandbox only counts once it has been tested with commands that try to escape it.
  • Agent runs need receipts. Model, prompt, tool list, permission verdicts, blocked actions, and an honest final state are being recorded per run, so a bad agent change can be traced and a control can be shown to have fired.

Production now

Playwright CLI for agents

Browser automation is becoming a native capability for coding and testing agents. Playwright CLI gives agents a compact, deterministic interface for inspection, test generation, execution, diagnosis, and repair without forcing every interaction through a large MCP tool surface.

Why it matters

This is a practical bridge between coding agents and mature browser automation. It also reinforces a broader pattern: use deterministic tools underneath the agent and reserve model reasoning for interpretation and decision making.

Agentic SDLC

The durable pattern is a governed workflow: agents handle interpretation and planning, deterministic systems handle reproducible execution, and policy boundaries control privileged actions.

  • Use agents where reasoning is valuable, not as a replacement for every deterministic step.
  • Separate read and reasoning privileges from write and deployment privileges.
  • Favor focused workflows that can be observed and evaluated over broad autonomy claims.
  • Start agent jobs with no network and no real credentials, and grant access per task.
